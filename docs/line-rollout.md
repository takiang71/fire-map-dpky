# แผนย้าย LINE ไปกลุ่มจริง (A7)

> เขียน 17 พ.ย. 69 ตามข้อ A7 ของ [review-2569-11-15.md](review-2569-11-15.md) · โค้ดที่เกี่ยว: `scripts/line_notify.js` (`LINE_MODE`, `TG_INVITE`), `worker/line-webhook.mjs` (`carousel({mode, tg})`) · ภาพรวมระบบแจ้งเตือน → [arch/notify.md](arch/notify.md)

## สรุปสั้น

- **โควตาฟรี 300 ข้อความ/เดือน นับ "ครั้งที่ push × จำนวนสมาชิกในกลุ่ม"** — กลุ่มจริง 11–30 คน **ใช้โหมดเดิม (all) ไม่ได้เลย** แม้เดือนที่ไฟน้อย
- โหมด `LINE_MODE=daily` (ส่งเฉพาะสรุปประจำวัน + การ์ดพื้นที่เผาไหม้) ใช้ ~36 ครั้ง/เดือน → **ฟรีได้ไม่เกิน 8 คน**
- **ข้อเสนอ**: (ก) LINE แบบ daily ในกลุ่มผู้บริหาร/ผู้ประสานงาน **≤ 8 คน** + ทุกคนรับแจ้งเตือนจุดใหม่ทันทีทาง Telegram (ไม่มีโควตา, ตอนนี้ 13 คน) · ถ้ากลุ่ม LINE ต้องมี 11–30 คน → (ข) อัปเกรดแพ็กเกจ (โหมดใดก็ได้)

## 1. ข้อมูลที่ใช้ประมาณ

**จำนวนครั้งที่ push แจ้งเตือนต่อวัน ≈ จำนวนรอบดาวเทียมที่มีจุดใหม่** (รอบ site ทุก 5 นาที ส่ง 1 ข้อความ/รอบ ถ้ามีจุดใหม่ — จุดของรอบดาวเทียมเดียวกันมักมาพร้อมกัน)
- คำนวณจาก `adata` (API ไทย + NASA FIRMS ทุกดวง SNPP/NOAA-20/NOAA-21) **ไม่รวม ขสป.ดงใหญ่/สถานีฯ ดงใหญ่** (ตรงกับ `excluded` ของ LINE) ช่วงหน้าแล้ง 1 ม.ค.–30 เม.ย. · รอบดาวเทียม = ดวงเดียวกัน วันเดียวกัน เวลาปัดช่วง 30 นาที
- ตรวจแบบจำลองกับของจริง: พ.ย. 69 (1–17) adata มีจุด 2 รอบ (1 พ.ย. 13:29, 17 พ.ย. 13:28) = log ของ LINE ส่งแจ้งเตือนจริง 2 ครั้งพอดี (กลุ่มตัวอย่างเล็ก — ถ้าต้นทางส่งจุดของรอบเดียวกันแยกหลายครั้ง จำนวนจริงอาจมากกว่านี้ราว 10–30%)

ข้อความอื่นที่ push (แต่ละรายการ = 1 ครั้ง × สมาชิก):
- สรุปประจำวัน 07:00 น. = 30–31 ครั้ง/เดือน (การ์ดพื้นที่เฝ้าระวัง จปร. แนบไปใน push เดียวกัน ไม่เพิ่ม)

- รายงานประจำเดือน (F3) = 1 ครั้ง/เดือน · ผลตรวจสอบจากหน้างาน (F1) = ตามจำนวนรายงาน (ยังไม่มีสถิติ ไม่รวมในตาราง)
- คำตอบคำสั่ง "สรุป"/"เผาไหม้" ในกลุ่มเป็น reply → **ไม่นับโควตา** (ข่าว LINE ประเทศไทย: ตั้งแต่ 1 ก.พ. 2570 reply ฟรีไม่เกิน 25,000 ข้อความ/เดือน — ระบบนี้ใช้ห่างจากเพดานมาก · ยังไม่ได้ตรวจกับประกาศทางการ)

| `daily` = สรุป + เผาไหม้ | 31 + 5 = **36** | **36** |

## 3. ทางเลือก

### (ก) LINE เฉพาะสรุปประจำวัน + Telegram เป็นช่องแจ้งเตือนจุด (`LINE_MODE=daily`) — แนะนำ
- LINE: สรุปประจำวัน 07:00 น. (+ การ์ด จปร.) และการ์ดพื้นที่เผาไหม้เมื่อมีรอบใหม่ · ใบ 1 ของสรุปมีบรรทัด "📲 แจ้งเตือนจุดใหม่ทันทีดูที่ Telegram แตะเข้ากลุ่ม ›" เมื่อตั้ง `TG_INVITE`
- ไม่ส่งทาง LINE: แจ้งเตือนจุดใหม่ (รวม จปร.), ผลตรวจสอบ F1, รายงานประจำเดือน F3 — ทั้งหมดยังส่งทาง Telegram · คำสั่ง "สรุป"/"เผาไหม้"/"เฝ้าระวัง" ในกลุ่ม LINE ยังใช้ได้ (reply ฟรี) ให้คนที่อยากดูสถานการณ์ล่าสุดกดเอง
- จุดที่เห็นระหว่างโหมด daily ถูกจำว่าเห็นแล้ว → สลับกลับเป็น all ไม่ส่งจุดเก่าย้อนหลัง
- ฟรีได้ ≤ 8 คน (288 ข้อความ/เดือน 31 วัน) — กลุ่ม 11–30 คนยังเกิน → ใช้คู่กับ (ข) หรือจำกัดกลุ่ม LINE ให้เป็นผู้บริหาร/ผู้ประสานงาน

### (ข) อัปเกรดแพ็กเกจ LINE OA
- ข้อมูลจากข่าว (ยังไม่ได้ตรวจกับหน้าราคาทางการ — ราคาเปลี่ยนบ่อย ตรวจที่ LINE Official Account Manager → การตั้งค่า → แพ็กเกจ ก่อนตัดสินใจ): Basic ประมาณ 1,200–1,280 บาท/เดือน 15,000 ข้อความ · Pro ประมาณ 1,500–1,780 บาท/เดือน 35,000 ข้อความ
- 30 คน โหมด all เดือนหนักสุด 3,480 ข้อความ → แพ็กเกจเล็กสุดพอ (ไม่ต้องแก้โค้ด: `quotaOk` อ่านเพดานจาก `/v2/bot/message/quota` เอง)
- ข้อเสีย: ค่าใช้จ่ายรายเดือน/การเบิกจ่ายของหน่วยงาน · ถ้าแพ็กเกจยอมให้ส่งเกินแล้วคิดเงินเพิ่ม ตัวกันยังหยุดที่เพดานที่ API รายงาน (ตั้ง `LINE_RESERVE` เผื่อได้)

### (ค) หลายกลุ่มเล็ก
- **โควตานับต่อบัญชี LINE OA ไม่ใช่ต่อกลุ่ม** — แยกเป็นหลายกลุ่มภายใต้บอทเดียวกัน ข้อความรวมเท่าเดิม ไม่ช่วยเลย
- ช่วยได้เฉพาะเมื่อแต่ละกลุ่มใช้ **LINE OA คนละบัญชี** (ได้ 300 ฟรีต่อบัญชี): เช่น 30 คน โหมด daily = 4 บัญชี × ≤8 คน · โหมด all = 15 บัญชี × 2 คน (ไม่สมเหตุสมผล)
- ต้องแก้โค้ด (ยังไม่ทำ): line_notify รองรับหลาย token/กลุ่ม + สถานะแยก, Worker LINE หลายตัวหรือหลาย secret, รหัสกลุ่มหลายชุด — ดูแลยากขึ้นมาก ขณะที่ Telegram ทำหน้าที่นี้ได้ฟรีอยู่แล้ว

### ตารางเปรียบเทียบ

| | (ก) daily + Telegram | (ข) อัปเกรด | (ค) หลายกลุ่ม/หลาย OA |
|---|---|---|---|
| ค่าใช้จ่าย | ฟรี | ~1,200–1,800 บาท/เดือน (ตรวจราคาก่อน) | ฟรี |
| สมาชิก LINE ที่รองรับ (ฟรี) | ≤ 8 | 30+ | 8 ต่อ OA |
| แจ้งเตือนจุดใหม่ทันทีใน LINE | ไม่ (ไป Telegram) | ได้ | daily: ไม่ / all: 2 คนต่อ OA |
| แก้โค้ด | เสร็จแล้ว (ตั้ง var 2 ตัว) | ไม่ต้อง | ต้องแก้มาก (ยังไม่ทำ) |
| ความเสี่ยงโควตาหมดกลางเดือน | ต่ำ (36 ครั้ง/เดือนคงที่) | ต่ำมาก | ปานกลาง |
| งานดูแล | ต่ำ | ต่ำ + เบิกจ่าย | สูง (หลายบัญชี/รหัส) |
| ผู้ใช้ต้องติดตั้งแอปเพิ่ม | Telegram (ผู้รับแจ้งเตือนทันที) | ไม่ | ไม่ |

## 4. ขั้นตอนย้ายกลุ่ม (เมื่อพร้อม — ผู้ใช้ทำเอง)

1. เชิญบอท "Hotspots สบอ.1" เข้ากลุ่มจริง → พิมพ์ "รหัสกลุ่ม" ในกลุ่ม (reply ฟรี) ได้รหัสขึ้นต้น `C…`
2. GitHub → Settings → Secrets and variables → Actions → **Variables**:
   - `LINE_GROUP_ID` = รหัสกลุ่มจริง
   - `LINE_MODE` = `daily` (ถ้าเลือก ก)
   - `TG_INVITE` = ลิงก์เชิญกลุ่ม Telegram (Telegram → กลุ่ม → เพิ่มสมาชิก → เชิญผ่านลิงก์ → คัดลอก `https://t.me/+…`) — ลิงก์ไม่ใช่ `https://t.me/…` จะไม่แสดง (log บอก)
3. Actions → **line-test** → Run workflow: `validate` ก่อน (ไม่เสียโควตา — มีแบบ "สรุปประจำวัน (LINE_MODE=daily + ลิงก์ Telegram)") แล้ว `daily` 1 ครั้งดูการ์ดจริงในกลุ่ม (เสียโควตาเท่าจำนวนสมาชิก)
4. ดูผล: `https://takiang71.github.io/fire-map-dpky/notify.json` (หรือ branch `state`)
   - `last` = ผลรอบล่าสุดทุกช่อง เช่น `{"mode":"daily","alert":"LINE_MODE=daily — ส่งทาง Telegram เท่านั้น","daily":"ส่งแล้ววันนี้","burn":null,…}`
   - `log` = 50 รายการล่าสุด: `why` = สาเหตุที่ไม่ส่ง (`LINE_MODE=daily …` + `mode:"daily"` / `โควตาไม่พอ …` + `quota:1` / `ไม่มีจุดใหม่`) — รอบติดกันที่เหตุเดียวกันรวมเป็นรายการเดียว (`x` = จำนวนรอบ, `t0` = รอบแรก, `t` = รอบล่าสุด)
   - `line.mode`, `line.members`, `line.left` (ตรวจทุกชั่วโมง ไม่เสียโควตา)
5. ถอยกลับ: ลบ var `LINE_MODE` (หรือตั้ง `all`) → กลับเป็นแบบเดิมรอบถัดไป · ตั้งค่าที่ไม่รู้จัก = all + ข้อความเตือนใน log ของ Actions
