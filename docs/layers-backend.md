# เครื่องมือวาด · Layer Manager · ระบบหลังบ้านชั้นข้อมูล

ปุ่ม **วาดและจัดการชั้นข้อมูล** (ไอคอนชั้นข้อมูลมีดินสอ ในแถวปุ่มควบคุมแผนที่) หรือลิงก์ท้ายแผงชั้นข้อมูล

## ใช้งาน (ทุกคน ไม่ต้องติดตั้งอะไร)

- **ปักหมุด / เส้นทาง / รูปหลายเหลี่ยม**
  - เมาส์: คลิกวางจุด · ดับเบิลคลิกหรือ Enter = จบ · คลิกจุดที่ 1 = ปิดรูป · Backspace = ย้อนจุด · Esc = เลิก
  - จอสัมผัส: เลื่อนแผนที่ให้กากบาทตรงตำแหน่ง แล้วกด **+ เพิ่มจุด** (แตะบนแผนที่ก็ได้)
  - จบแล้วกรอก ชื่อ / รายละเอียด / สี / ข้อมูลเพิ่มเติม แล้วกด **บันทึก**
  - ก่อนบันทึก: ลากจุดเพื่อย้าย · ลากหรือคลิกจุดเล็กกลางเส้นเพื่อเพิ่มจุด · ดับเบิลคลิกจุดเพื่อลบ
  - แสดงความยาว (ม./กม.) พื้นที่ (ไร่-งาน-ตร.ว.) และพิกัด UTM ระหว่างวาด
- **แตะวัตถุบนแผนที่** = ดูรายละเอียด ระยะ/พื้นที่ แก้ไข ลบ คัดลอกพิกัด นำทาง
  - พื้นที่จะขึ้นเป็นบรรทัดบนสุดของป๊อปอัปตำแหน่ง (ไม่บังข้อมูลอากาศ/ตำบล)
- **ชั้นในเครื่อง** เก็บในเบราว์เซอร์นั้นเท่านั้น (IndexedDB) — ล้างข้อมูลเบราว์เซอร์แล้วหาย ควรส่งออกเก็บไว้
- **นำเข้า** (ปุ่มนำเข้าไฟล์ หรือลากไฟล์มาวางที่แผง เลือกหลายไฟล์พร้อมกันได้)
  - GeoJSON · Esri JSON · KML/KMZ (คงสีและโฟลเดอร์) · GPX · CSV · Shapefile (.zip หรือเลือก .shp .dbf .prj .cpg พร้อมกัน)
  - CSV อ่านคอลัมน์ ละติจูด/ลองจิจูด (lat/lon, องศาลิปดาฟิลิปดาได้) · UTM (x/y, easting/northing + คอลัมน์โซน ไม่มี = 47) · WKT
  - ระบบพิกัด: WGS84, UTM WGS84 ทุกโซน, Indian 1975 UTM 47/48 (แปลงด้วยค่ากรมแผนที่ทหาร 204.4798, 837.8940, 294.7765), Web Mercator · ระบบอื่นใน .prj โหลด proj4 จาก cdnjs มาแปลง
  - ไม่มี .prj แต่ค่าพิกัดเป็นเมตร = ถือว่าเป็น UTM 47N (แจ้งเตือนในผลการนำเข้า)
  - .dbf ภาษาไทยอ่านตาม .cpg หรือเดา UTF-8 / TIS-620 ให้
- **ส่งออก** (ปุ่มส่งออก… หรือเมนู ⋯ ของชั้น) เลือกได้หลายชั้น
  - KMZ / KML (หลายชั้น = แยกโฟลเดอร์ คงสี)
  - Shapefile .zip — แยกไฟล์ตามชนิด จุด/เส้น/พื้นที่ · WGS84 หรือ UTM 47N/48N · UTF-8 + .cpg
    - DBF จำกัดชื่อคอลัมน์ 10 ไบต์ (ภาษาไทยได้ ~3 ตัว) — ถ้าถูกตัดจะมีไฟล์ `ชื่อคอลัมน์เต็ม.txt` ใน zip
  - GeoJSON · GPX (หมุด = waypoint, เส้น/ขอบพื้นที่ = track) · CSV (Excel, มีคอลัมน์ WKT)

## ติดตั้งระบบหลังบ้าน (ครั้งเดียว ฟรี — Cloudflare Worker + KV)

ใช้บัญชี Cloudflare เดิม (บัญชีเดียวกับ Worker ของ LINE bot)

1. Cloudflare → **Workers & Pages → Create → Create Worker**
   - ตั้งชื่อ **`fire-layers`** (เว็บเรียก `https://fire-layers.takiang71.workers.dev` — ถ้าใช้ชื่ออื่นต้องแก้ `UL_API` ใน index.html)
   - กด Deploy → **Edit code** → ลบโค้ดเดิม วางทั้งไฟล์ `worker/layers.mjs` → **Deploy**
2. **Storage & Databases → KV → Create** ตั้งชื่อ `fire-layers`
3. เปิด Worker `fire-layers` → **Settings → Bindings → Add → KV namespace**
   - Variable name: **`LAYERS`** · KV namespace: `fire-layers` → Deploy
4. **Settings → Variables and Secrets → Add**
   - Type: **Secret** · Name: **`ADMIN_PASS`** · Value: รหัสผ่านผู้ดูแลหลัก (ยาวๆ เดายาก) → Deploy
5. ตรวจ: เปิด `https://fire-layers.takiang71.workers.dev/` ต้องเห็น `{"ok":true,...,"kv":true,"admin":true}`
6. ที่หน้าเว็บ: แผงเครื่องมือ → **เข้าสู่ระบบ** ชื่อผู้ใช้ `admin` + รหัสจากข้อ 4 → **จัดการหลังบ้าน**

## หลังบ้าน (ผู้ดูแล)

- **กลุ่ม**: สร้างกลุ่ม เช่น "สถานีควบคุมไฟป่าทับลาน"
- **ผู้ใช้**: ชื่อผู้ใช้ (a-z 0-9 _ . -) + รหัสผ่าน ≥ 8 ตัว + กลุ่ม · ติ๊ก "ผู้ดูแล" ให้จัดการหลังบ้านได้
  - **ปิดใช้งาน** = เข้าไม่ได้ทันที · ตั้งรหัสใหม่ให้ได้ · ผู้ใช้เปลี่ยนรหัสเองได้ (เมนูเปลี่ยนรหัสผ่าน)
- **ชั้นข้อมูล**: วาด/นำเข้าเป็นชั้นในเครื่องก่อน → **+ อัปโหลดชั้นในเครื่องขึ้นเซิร์ฟเวอร์** (หรือเมนู ⋯ ของชั้น)
  - ใครเห็น: **ทุกคน** (ไม่ต้องล็อกอิน = เปิดเผยสาธารณะ) / **ทุกคนที่เข้าสู่ระบบ** / **เฉพาะกลุ่มหรือผู้ใช้ที่เลือก**
  - เปิดแสดงเป็นค่าเริ่มต้น · อนุญาตให้ส่งออก/คัดลอก
  - แก้ข้อมูลชั้นบนเซิร์ฟเวอร์: เมนู ⋯ → **คัดลอกลงเครื่อง** → แก้ → เมนู ⋯ ของชั้นในเครื่อง → **อัปเดตชั้นบนเซิร์ฟเวอร์**
- ผู้ดูแลหลัก `admin` ไม่อยู่ในรายชื่อผู้ใช้ เปลี่ยนรหัสได้ที่ Secret `ADMIN_PASS` เท่านั้น (เปลี่ยนแล้ว token เดิมของ admin ใช้ไม่ได้)
- **บันทึกการใช้งาน** (แท็บที่ 4 ของหลังบ้าน, E3 17 พ.ย. 69): 200 รายการล่าสุด — ใคร · การกระทำ · ชั้น/รายงาน/ผู้ใช้/กลุ่มใด · เวลา · กรองตามประเภทได้ (รายละเอียดหัวข้อ E3 ด้านล่าง)
- **ออกจากระบบทุกอุปกรณ์**: ทุกบัญชี (รวม admin) กดได้เองที่แถบบัญชีในแผงชั้นข้อมูลของฉัน

## รายงานผลตรวจสอบจากหน้างาน (F1, 16 พ.ย. 69)

Worker เดิมเพิ่ม endpoint (ไม่ต้องเพิ่ม binding/secret — ใช้ KV `LAYERS` และบัญชีเดิม) · **อัปเดต Worker: Workers & Pages → fire-layers → Edit code → ลบโค้ดเดิม วางทั้งไฟล์ `worker/layers.mjs` → Deploy** แล้วเปิด `https://fire-layers.takiang71.workers.dev/` ต้องเห็น `"rep":true`

| Endpoint | สิทธิ์ | หน้าที่ |
|---|---|---|
| `GET /reports?fy=2570` | ทุกคน | รายงานของปีงบ (ไม่ระบุ = ปีงบปัจจุบัน) → `{fy, reports}` — build_site.js ดึงปีงบนี้+ปีก่อนทุกรอบเป็น `_site/reports.json` |
| `POST /reports` | ล็อกอิน | body JSON ≤ 8 KB `{res*, hk, hs:{la,lo,t,sat}, rai, cs, rp, ta, te, un, pl, moo, note, pos:[lo,la,acc], ar, st, tm}` · `res` = fire/none/out/plan · Worker ตัดความยาว/ตรวจช่วงค่า · ปีงบคิดจาก `hs.t` (ไม่มี = เวลาบันทึก) · ตอบ `{report}` |
| `PUT /reports/<id>?fy=` · `DELETE …` | เจ้าของภายใน 24 ชม. หรือผู้ดูแล | แก้ (ช่องที่ส่งมาเท่านั้น, บันทึก `ed` ผู้แก้) / ลบ |
| `POST /reports/repair?fy=` | ผู้ดูแล | สร้างดัชนี `rep:<fy>` ใหม่จากสำเนา `r:<id>` (ใช้เมื่อเขียนชนกันแล้วรายการหาย) |

- KV: `rep:<ปีงบ>` = อาร์เรย์ระเบียน (อ่าน 1 ครั้ง/คำขอ) + `r:<id>` สำเนาเดี่ยว · ระเบียน `{id,fy,hk,hs,res,rai,cs,rp,ta,te,un,pl,moo,note,pos,ar,st,tm,by:{u,d},c,m,ed?}` · `hk` = hKey ของจุดในหน้าเว็บ (`วัน|HHMM|lat×1e3|lon×1e3`)
- เฟสแรก**ไม่เก็บภาพ** (ผู้ใช้ตัดสิน 16 พ.ย. 69) · KV ไม่มี transaction: สองคนบันทึกในวินาทีเดียวกันคนละ edge อาจเสียรายการในดัชนี → มี `r:<id>` + repair เป็นตาข่ายนิรภัย · ทีมใหญ่ขึ้นค่อยย้ายไป Durable Objects
- ทดสอบ: `test/layers.test.js` (KV จำลอง 13 ข้อ รวม login/ชั้นข้อมูล/รายงาน + E3 9 ข้อ + F7 2 ข้อ) · หน้าเว็บ: โมดูล `VF` ใน index.html → [arch/ui-modules.md](arch/ui-modules.md)

## บันทึกการดับไฟป่า จากเมนูไฟป่าที่ตรวจพบ (18 พ.ย. 69)

**ต้องวาง Worker ใหม่** (Workers & Pages → fire-layers → Edit code → วางทั้งไฟล์ `worker/layers.mjs` → Deploy) แล้วเปิด `https://fire-layers.takiang71.workers.dev/` ต้องเห็น `"fd":true` — ก่อน deploy หน้าเว็บจะไม่ส่ง (บอกให้ผู้ดูแลวาง Worker ใหม่)

| ช่องใหม่ใน `POST/PUT /reports` | ค่า |
|---|---|
| `kd` | `"fd"` = มาจากฟอร์มบันทึกการดับไฟป่า (ค่าอื่น = null) |
| `tn` | เวลารับแจ้งเหตุ (ms) 0–4e12 · ผิดรูป = null |
| `ag` | หน่วยงานที่ปฏิบัติ ≤ 120 ตัวอักษร |
| `crew` | จำนวนผู้ปฏิบัติ 0–9999 (ว่าง/null = null) |

- ปีงบของระเบียน `repFy` = `hs.t` → `tn` → เวลาบันทึก (เดิม hs.t → เวลาบันทึก) · `PUT` ที่ทำให้ปีงบเปลี่ยน (แก้วันที่) = ย้ายจาก `rep:<เดิม>` ไป `rep:<ใหม่>` และ `r:<id>.fy` ตาม
- ไม่มีเอนด์พอยต์ใหม่ · ไม่เพิ่มการเขียน KV (ย้ายปีงบ +1 ครั้ง) · สิทธิ์เดิม (บันทึก = ล็อกอิน, แก้/ลบ = เจ้าของ 24 ชม./ผู้ดูแล)
- **19 พ.ย. 69 รุ่น `fd:2`** (ต้อง deploy อีกครั้ง — หน้าเว็บตรวจ `fd>=2`): `csx` สาเหตุอื่นๆ ≤120 · `rn` ชื่อผู้รายงาน ≤120 · `rt` เบอร์โทร (ตัดช่องว่าง/ขีด ต้องเป็น 0 + 8–9 หลัก ไม่งั้น "") · **`GET /reports` ตัด `rt` ออก (`repPub`) ยกเว้นผู้ดูแล/เจ้าของ** → `reports.json` สาธารณะไม่มีเบอร์ (build_site ดึงแบบไม่ล็อกอิน)
- ทดสอบ: `test/layers.test.js` ข้อ "reports fd" และ "reports fd: csx/rn/rt"

## E3 ขนาดอัปโหลด · ออกจากระบบทุกอุปกรณ์ · บันทึกการใช้งาน (17 พ.ย. 69)

**ต้องวางโค้ด Worker ใหม่**: Workers & Pages → fire-layers → Edit code → ลบโค้ดเดิม วางทั้งไฟล์ `worker/layers.mjs` → Deploy แล้วเปิด `https://fire-layers.takiang71.workers.dev/` ต้องเห็น `"log":true,"max_mb":8` (ไม่ต้องเพิ่ม binding/secret) · ก่อนวางโค้ดใหม่ หน้าเว็บยังใช้ได้: ปุ่มออกจากระบบทุกอุปกรณ์/แท็บบันทึก แจ้ง "เซิร์ฟเวอร์ยังไม่รองรับ"

| Endpoint | สิทธิ์ | หน้าที่ |
|---|---|---|
| `POST /layers` · `PUT /layers/<id>/data` | ผู้ดูแล | body ≤ **8 MB** (นับไบต์ — ไทย 3 ไบต์/ตัว; ตรวจ `content-length` ก่อนอ่าน body แล้วตรวจขนาดจริงซ้ำ) เกิน = **413** `{"error":"ไฟล์ใหญ่เกิน 8 MB (ขนาด X MB) — ลดจำนวนวัตถุ/จุดของเส้น หรือแบ่งเป็นหลายชั้น"}` · หน้าเว็บตรวจขนาดก่อนส่ง (`ulBig`) ข้อความเดียวกัน |
| `POST /logout-all` | ล็อกอิน | ออกจากระบบทุกอุปกรณ์ของ**บัญชีตัวเอง** (รวมเครื่องที่กด): ผู้ใช้ = เปลี่ยน `v` ใน meta.users · ผู้ดูแลหลัก = ตั้ง `meta.rv` ใหม่ (รุ่น token admin = sha(ADMIN_PASS + "\|" + rv); ไม่มี rv = แบบเดิม จึงไม่หลุดตอน deploy) → `{ok:true}` · รหัสผ่านไม่เปลี่ยน |
| `GET /log` | ผู้ดูแล (ผู้ใช้ทั่วไป 403, ไม่ล็อกอิน 401) | `{log:[…], max:200}` ใหม่สุดก่อน |

- KV `log` = อาร์เรย์ ≤ 200 รายการ `{t, u, d, a, k, id, n, fy, x}` — `t` เวลา ms · `u`/`d` ชื่อผู้ใช้/ชื่อที่แสดงของผู้กระทำ · `a` การกระทำ · `k` ประเภท layer/report/user/group/auth · `id` รหัสชั้น/รายงาน/ชื่อผู้ใช้/กลุ่ม · `n` ชื่อชั้น/ตำบลของรายงาน/ชื่อที่แสดง/ชื่อกลุ่ม · `fy` ปีงบของรายงาน · `x` รายละเอียดสั้น (ขนาด KB, ผล fire/none/out/plan, สิ่งที่แก้ของผู้ใช้ เช่น "ปิดใช้งาน · ตั้งรหัสผ่านใหม่", ชื่อกลุ่มเดิม)
- การกระทำ: `login` · `lock` (ใส่รหัสผิดครบ 8 ครั้ง — **บันทึกเฉพาะชื่อผู้ใช้ที่มีจริง** กันรหัสผ่านที่พิมพ์ผิดช่องลงบันทึก) · `logout-all` · `password` · `layer-add` `layer-data` `layer-edit` `layer-del` · `rep-add` `rep-edit` `rep-del` `rep-repair` (F1 `/reports`) · `user-add` `user-edit` `user-del` · `group-add` `group-edit` `group-del`
- **ไม่เก็บ**: รหัสผ่าน (ทั้งถูก/ผิด), token, แฮช/salt, เนื้อหาชั้น, หมายเหตุ/พิกัดของรายงาน, IP — ตรวจในเทสต์ (`test/layers.test.js` ค้นรหัสผ่าน/token ทุกตัวที่ใช้ในเทสต์ในข้อความ KV ทั้งก้อน)
- เขียนบันทึก = อ่าน+เขียน KV เพิ่ม 1 ครั้งต่อการกระทำ (โควตาเขียนฟรี 1,000/วัน: รายงาน F1 = 3 ครั้ง/รายงาน, login = 1) · บันทึกล้มเหลว (เช่น โควตาเขียนเต็ม) ไม่ทำให้คำสั่งหลักล้ม
- KV ไม่มี transaction: สองคำขอพร้อมกันอาจทำให้รายการหายบางรายการ — ใช้ตรวจสอบเบื้องต้น ไม่ใช่หลักฐานครบถ้วน
- หน้าเว็บ: แท็บ "บันทึกการใช้งาน" ใน `ulAdmin` (`ulALog`/`ualDraw`, ชื่อการกระทำภาษาไทย `UALA`, กรอง `UALK`) · ลิงก์ "ออกจากระบบทุกอุปกรณ์" ใน `#ul-acc` (`ulLogAll`, ยืนยันก่อน) · ตรวจขนาดก่อนส่ง `ULMAX`/`ulBig` ใน `ulApi`
- ทดสอบ: `test/layers.test.js` เพิ่ม 9 เทสต์ (413 ไทย/ASCII/PUT data/content-length, ออกทุกอุปกรณ์ผู้ใช้ + admin, บันทึกครบการกระทำ/ไม่มีข้อมูลลับ/ผู้ใช้ทั่วไปอ่านไม่ได้/200 รายการ/บันทึกล้มเหลว) · check_site ขั้น `E3UI` (เดสก์ท็อป+มือถือ, ulApi จำลอง)

## F7 แนบเส้นทางเดินกับรายงาน (18 พ.ย. 69)

**ต้องวางโค้ด Worker ใหม่**: Workers & Pages → fire-layers → Edit code → ลบโค้ดเดิม วางทั้งไฟล์ `worker/layers.mjs` → Deploy แล้วเปิด `https://fire-layers.takiang71.workers.dev/` ต้องเห็น `"trk":true` (ไม่ต้องเพิ่ม binding/secret) · **ก่อนวางโค้ดใหม่**: บันทึกรายงานได้ตามเดิม แต่ถ้าเลือก "แนบเส้นทางเดิน" หน้าเว็บจะแจ้ง "เซิร์ฟเวอร์ยังไม่รองรับการแนบเส้นทาง — ผู้ดูแลต้องวาง Worker รุ่นใหม่" (ตรวจ `GET /` → `trk` ก่อนส่ง) และไม่ส่ง

| Endpoint | สิทธิ์ | หน้าที่ |
|---|---|---|
| `POST /reports` · `PUT /reports/<id>?fy=` | เดิม | ช่องใหม่ `trk` = `{c:[lon,lat,lon,lat,…], t0, t1, km, up, dn, n}` — `c` ≤ **500 จุด** (หน้าเว็บย่อด้วย Douglas-Peucker ก่อนส่ง) ปัด 5 ตำแหน่ง (~1 ม.) · `trk:null` = ลบเส้นทางที่แนบ · ไม่ส่ง = คงเดิม · ผิดรูป/เกิน 500 จุด = ไม่เก็บ (`trk:null`) ตามกติกาค่าผิดรูป · body: ส่วนที่ไม่ใช่เส้นทาง ≤ 8 KB เท่าเดิม + เส้นทาง ≤ 16 KB (รวมเกิน = 413) |
| `GET /reports/<id>/trk` | ทุกคน (เหมือนรายงาน) | `{id, trk:{c, m, n, km, up, dn, t0, t1}}` · ไม่มี = 404 |
| `DELETE /reports/<id>?fy=` | เดิม | ลบคีย์เส้นทาง `t:<id>` ด้วย |

- KV: พิกัดเส้นทางอยู่คีย์แยก `t:<id>` — **ไม่อยู่ในดัชนี `rep:<fy>`** เพราะดัชนีถูกอ่าน/parse ทุกคำขอ ถ้ามีเส้นทาง ~10 KB ต่อรายงาน ดัชนีจะใหญ่จน JSON.parse เกิน CPU 10 ms ของ Worker ฟรี · ระเบียน (และ `r:<id>`) เก็บแค่สรุป `trk:{m จุดที่เก็บ, n จุดเดิมก่อนย่อ, km, up, dn, t0, t1}` → `reports.json` บน Pages มีแค่สรุป ไม่มีพิกัดเส้นทาง · KV เขียนเพิ่ม 1 ครั้งต่อรายงานที่แนบเส้นทาง
- หน้าเว็บ: ช่อง "แนบเส้นทางเดิน" ในฟอร์ม `vfForm` (`tkVfHtml`/`tkVfVal`/`tkPack`/`tkCap`) · ปุ่ม "ดูเส้นทาง" ในกล่องผลตรวจสอบ (`tkView` → ชั้น `tk-v`) → [arch/ui-modules.md](arch/ui-modules.md) หัวข้อ "บันทึกเส้นทาง (F7)"
- **ความเป็นส่วนตัว**: เส้นทางที่บันทึกอยู่ใน IndexedDB ของเครื่อง (`fm-tk` ระหว่างบันทึก → ชั้นข้อมูลของฉัน `fm-ul`) ไม่ถูกส่งไปที่ใดจนกว่าผู้ใช้เลือกแนบกับรายงานเอง · เส้นทางที่แนบแล้วอ่านได้ทุกคน (เหมือนรายงาน) ฟอร์มบอกผู้ใช้ก่อนส่ง
- ทดสอบ: `test/layers.test.js` 2 เทสต์ (แนบ 500 จุด/คีย์แยก/สรุปในดัชนีและ r:<id>/อ่านไม่ล็อกอิน/แทนที่/ลบด้วย null/ลบรายงาน · เกิน 500 จุด/พิกัดผิด/รูปผิด = ไม่เก็บ · 8 KB นอกเส้นทาง/รวมเกิน = 413) — **ยังไม่ได้ลองกับ Cloudflare จริง**

## SYS ภาพรวมระบบ · ตั้งค่าระบบ · นับผู้เข้าชม (20 พ.ย. 69)

ผู้ใช้ขอ "ระบบหลังบ้านของผู้ดูแลให้เข้าดูการทำงานของเว็บทั้งหมด: สถานะระบบ จำนวนผู้เข้าชม ความจุบนคลาวด์ สมาชิก การปิด-เปิดฟังก์ชัน ฯลฯ" → แท็บใหม่ 2 แท็บในหน้า **จัดการหลังบ้าน** (ลิงก์ "จัดการหลังบ้าน" เปิดแท็บภาพรวมระบบเป็นแท็บแรก)

### ติดตั้ง (ผู้ดูแลทำเองใน Cloudflare — ยังไม่ได้ทำ ณ 20 พ.ย. 69)

1. **วางโค้ด Worker ใหม่** (จำเป็น): Workers & Pages → `fire-layers` → Edit code → ลบโค้ดเดิม วางทั้งไฟล์ `worker/layers.mjs` → Deploy → เปิด `https://fire-layers.takiang71.workers.dev/` ต้องเห็น `"sys":1`
   - ก่อนวาง: แท็บภาพรวมระบบยังแสดงสถานะจาก Pages/GitHub ได้ แต่ส่วนจากเซิร์ฟเวอร์ขึ้น "เซิร์ฟเวอร์ยังไม่รองรับ…" · แท็บตั้งค่าระบบใช้ไม่ได้
2. **ผูกฐานข้อมูล D1 สำหรับนับผู้เข้าชม** (ไม่บังคับ แต่ไม่ทำ = ไม่มีตัวเลขผู้เข้าชม/สมาชิกที่ใช้งานล่าสุด):
   - Storage & Databases → **D1 SQL Database → Create** ตั้งชื่อ `fire-stats` (ตารางสร้างเองตอนใช้ครั้งแรก ไม่ต้องรัน SQL)
   - Worker `fire-layers` → Settings → Bindings → Add → **D1 database** · Variable name: **`DB`** · Database: `fire-stats` → Deploy
   - ตรวจ: `GET /` ต้องเห็น `"db":true`
3. **โควตา Cloudflare จริงของวันนี้** (ไม่บังคับ): My Profile → API Tokens → Create Token → Custom token สิทธิ์ **Account → Account Analytics → Read** (บัญชีนี้บัญชีเดียว) → คัดลอก token
   - Worker `fire-layers` → Settings → Variables and Secrets → Add **Secret `CF_API_TOKEN`** = token และ **`CF_ACCOUNT_ID`** = Account ID (หน้า Workers & Pages ด้านขวา) → Deploy
   - ตรวจ: `GET /` ต้องเห็น `"cf":true` · ถ้าแท็บขึ้น "อ่านบางชุดไม่ได้" = ชื่อชุดข้อมูล GraphQL ใน `cfStats` อาจไม่ตรงกับของ Cloudflare (**ยังไม่ได้ลองกับบัญชีจริง** — ทดสอบกับ GraphQL จำลองเท่านั้น)

### Endpoint ใหม่ใน `worker/layers.mjs`

| Endpoint | สิทธิ์ | หน้าที่ |
|---|---|---|
| `POST /hit` | ทุกคน | นับการเปิดหน้าเว็บ body ≤ 512 ไบต์ `{d:'m'\|'d', n, f, a, s:'ln'\|'tg'\|'fb'\|'ot'\|'', l}` → **204 เสมอ** (ไม่มี DB/บอต/ผิดรูป ก็ 204) · ทำก่อนอ่าน meta = **ไม่ใช้ KV** · เขียน D1 1 แถว/ครั้ง (upsert ตาราง `hit` รายชั่วโมง) |
| `GET /flags` | ทุกคน | `{flags:{ann, login, rep, hl, lnd, off, upd}}` — build_site.js ดึงทุกรอบ → `_site/flags.json` |
| `PUT /flags` | ผู้ดูแล | แก้สวิตช์ (ส่งเฉพาะช่องที่จะแก้) · ตรวจค่า · ลงบันทึก `flags` (ประเภท `sys`) เฉพาะเมื่อมีการเปลี่ยน |
| `GET /sys` | ผู้ดูแล (ไม่ล็อกอิน 401, ผู้ใช้ทั่วไป 403) | ภาพรวม: flags · จำนวนผู้ใช้/ผู้ดูแล/ปิดใช้งาน/กลุ่ม · ชั้น (จำนวน/KB/สาธารณะ) · รายงานปีงบนี้/ก่อน · บันทึก (ล็อกอิน/ล็อก 7 วัน) · ขนาด meta · `visits` (รายวัน 90 วัน/รายชั่วโมง 2 วัน/รายเดือน 13 เดือน) · `seen` สมาชิกที่ใช้งานล่าสุด · `cfq` โควตา Cloudflare (ถ้าตั้ง token) |
| `GET /layers` | เดิม | เพิ่ม `flags` (หน้าเว็บทุกเครื่องเรียกอยู่แล้ว 1.5 วิหลังเปิด → สวิตช์มีผลทันทีโดยไม่เพิ่มคำขอ/การอ่าน KV) |
| `GET /` | ทุกคน | เพิ่ม `sys:1, db, cf` |

- **สวิตช์** (`meta.flags` ใน KV — ไม่มี = เปิดทุกอย่าง):
  - `ann` ประกาศ `{t ≤300 ตัวอักษร, lv info|warn|crit, until ms|0, id}` — id ใหม่เมื่อข้อความเปลี่ยน (คนที่กดปิดประกาศเดิมจะเห็นข้อความใหม่) · หมดเวลา `until` = ไม่ส่ง
  - `login:false` = ผู้ใช้ทั่วไป**เข้าสู่ระบบใหม่**ไม่ได้ (403, ตรวจหลังรหัสถูก — รหัสผิดยัง 401 เหมือนเดิม) · ผู้ดูแลเข้าได้ · token เดิมยังใช้ได้ (ตัดทันที = ปิดใช้งานรายบัญชี)
  - `rep:false` = ผู้ใช้ทั่วไป POST/PUT/DELETE `/reports` ไม่ได้ (403) · ผู้ดูแลทำได้ · อ่านได้ตามเดิม · หน้าเว็บ `syGate('rep')` ใน `vfForm`/`fdForm` บอกก่อนเปิดฟอร์ม
  - `hl` = รายการ `data-k` ของสวิตช์ชั้นข้อมูลที่ซ่อนจากผู้ใช้ทั่วไป (≤80, `[a-zA-Z0-9_-]{1,24}`) — หน้าเว็บซ่อนแถว + ปิดชั้นที่เปิดอยู่ · ผู้ดูแลเห็นแบบกรอบประ · ซ่อน `hot` (จุดความร้อน) และ `d3` ไม่ได้
  - `lnd` = LINE_MODE=daily · `off` = ตัวแปรใน `NOFF` (LINE_DAILY/BURN/REP/MREP, TG_DAILY/BURN/REP/MREP/SUBS) เป็น off — **ปิดได้อย่างเดียว** (ตัวแปร Actions ที่ตั้ง off ไว้ยัง off) · มีผลรอบ site ถัดไป: build_site → `_site/flags.json` (ดึงไม่ได้ = ฉบับบนเว็บรอบก่อน) → `scripts/lib/flags.js applyEnv()` ต้นไฟล์ line_notify/telegram_notify
  - ไม่มีสวิตช์ "หยุดแจ้งเตือนจุดใหม่ทั้งหมด" โดยตั้งใจ (ถ้าปิดแล้วลืม จุดไฟจะไม่ถูกแจ้ง) — ลดโควตา LINE ใช้ `lnd`
- **D1** ตาราง `hit(day TEXT วันไทย, h ชั่วโมงไทย, pv, uv, nu, mob, app, ln, tg, fb, ot, dl)` PK (day,h) · `seen(u, t, n)` บันทึกตอน login และ GET /me เมื่อห่างครั้งก่อน > 1 ชม. (`n` ≈ จำนวนช่วงการใช้งาน) · `GET /sys` ลบ `hit` เก่ากว่า 400 วัน
  - **ไม่เก็บ** IP, user-agent, รหัสเครื่อง, หน้าที่เปิด · "คน" = เบราว์เซอร์ที่เปิดครั้งแรกของวัน (localStorage `fm-hitd`; โหมดไม่ระบุตัวตนนับทุกครั้ง) · ไม่นับ localhost/IP ภายใน/file:/`navigator.webdriver`/UA บอต/เครื่องที่ผู้ดูแลติ๊ก "ไม่นับเบราว์เซอร์นี้" (`fm-nohit`)
  - ใครก็ POST /hit ได้ (ปั่นตัวเลขได้) — ตัวเลขใช้ดูแนวโน้ม ไม่ใช่สถิติทางการ
- **โควตา** (`cfStats`): GraphQL `workersInvocationsAdaptive` · `kvOperationsAdaptiveGroups` · `kvStorageAdaptiveGroups` · `d1AnalyticsAdaptiveGroups` · `d1StorageAdaptiveGroups` ถามแยกชุด (ชุดใดผิดพลาด = `err.<ชุด>` ชุดอื่นยังได้) · วันตาม UTC (โควตาฟรีรีเซ็ต 07:00 น. ไทย) · นับทั้งบัญชี (ทุก Worker/namespace)
- ค่าใช้จ่ายเพิ่ม: เปิดหน้าเว็บ = Worker +1 คำขอ (`/hit`) + D1 เขียน 1 แถว · ไม่เพิ่มการอ่าน/เขียน KV ยกเว้น `GET /sys` (อ่าน 3: rep ปีนี้/ปีก่อน/log) และ `PUT /flags` (เขียน meta + log) · build_site อ่าน `GET /flags` ทุกรอบ ≈ 288 อ่าน KV/วัน
- หน้าเว็บ: โมดูล `SY` ใน index.html → [arch/ui-modules.md](arch/ui-modules.md) หัวข้อ "SYS ภาพรวมระบบ"
- ทดสอบ: `test/sys.test.js` (D1 จำลองด้วย `node:sqlite` = SQL จริง · KV จำลอง · GraphQL จำลอง · lib/flags) · check_site ขั้น `SYUI` (เดสก์ท็อป+มือถือ)

## ข้อจำกัด / ความปลอดภัย

- โควตาฟรี: Worker 100,000 คำขอ/วัน · KV อ่าน 100,000/วัน เขียน 1,000/วัน พื้นที่ 1 GB
  - เปิดหน้าเว็บ 1 ครั้ง = อ่าน KV 1 ครั้ง (+1 ต่อชั้นที่เปิด) · การเขียนเกิดเฉพาะตอนผู้ดูแลแก้
- ชั้นละไม่เกิน **8 MB** (GeoJSON, E3 17 พ.ย. 69 — เดิม 20 MB) เกิน = 413
- KV อาจใช้เวลาถึง ~60 วินาทีกว่าการแก้ไขจะเห็นทุกที่
- ข้อมูลชั้นเก็บใน KV ไม่อยู่ใน repo สาธารณะ · ชั้น "เฉพาะกลุ่ม" ดาวน์โหลดได้เฉพาะผู้มี token ที่ถูกต้อง
- รหัสผ่านเก็บแบบ PBKDF2-SHA256 + salt · token อายุ 30 วัน · ใส่รหัสผิด 8 ครั้ง = ล็อก 15 นาที (ลงบันทึก `lock`) · ออกจากระบบทุกอุปกรณ์ = token เดิมทุกใบใช้ไม่ได้ทันที
- ชั้นที่ตั้ง "ทุกคน" ใครก็ดาวน์โหลดได้ — ห้ามใช้กับข้อมูลลับ
- รายงานผลตรวจสอบเป็นสาธารณะ (อ่านได้ไม่ต้องล็อกอิน แสดงชื่อแสดงของผู้บันทึก) · บันทึกได้ทุกบัญชีที่ล็อกอิน · เขียน KV 2 ครั้งต่อรายงาน (โควตาเขียน 1,000/วัน)
