# แบบรับแจ้งเหตุไฟป่า กรมอุทยานฯ (Google Forms/Sheets) → การดับไฟป่าบนเว็บ — prefix `DF`

## การตัดสินใจของผู้ใช้ (19 พ.ย. 69)
1. ผู้ใช้ถามว่าบันทึกการดับไฟในเว็บ (FD) แล้วส่งเข้าแบบรับแจ้งเหตุของกรมฯ อัตโนมัติได้ไหม (ปีงบ 2570 ไม่ต้องทำงานซ้ำ)
2. ตรวจแล้ว: **ฟอร์มจริงเก็บอีเมลแบบยืนยันตัวตน** (`FB_PUBLIC_LOAD_DATA_[1][10][6]=2`, ช่องติ๊ก "บันทึกอีเมลของฉันพร้อมกับคำตอบของฉัน") ผู้ส่งต้องล็อกอิน Google ในเบราว์เซอร์ของตัวเอง → เว็บ/Worker ส่งแทนไม่ได้ · การล็อกอินด้วย Google บนเว็บเราก็ไม่ช่วย (Forms API ส่งคำตอบไม่ได้) · ทางที่ทำได้คือลิงก์กรอกล่วงหน้าให้กดส่งเอง (ทดสอบกับฟอร์มสำเนาแล้ว)
3. ผู้ใช้เห็นว่ายุ่งยาก → **กลับทิศ: ดึงตารางคำตอบที่เจ้าหน้าที่กรอกมาแสดงบนเว็บ** และ **ซ่อนฟอร์ม FD ของเว็บ**
- อย่ากลับไปเปิดฟอร์ม FD หรือทำระบบส่งเข้าฟอร์มกรมฯ โดยไม่ถามผู้ใช้

## แปลงแถว `rowOf` (ตรวจกับ Excel อส. ปีงบ 2569 — ชุดเดียวกัน 153/153 แถว วัน+E+N ตรง, เวลารับแจ้งตรงทุกแถว, ไร่ตรง 151)
- กลุ่มป่า = `where()` (แนวเขต) หรือพื้นที่ป่าตรง `AREA` หรือสถานีฯ ตรง `STAT` (รายการชื่อในฟอร์มปีงบ 2569)
- พิกัด: Zone + X/Y (ช่วงเดียวกับ import_fx) → `utmToLL` · ตำบล/อำเภอ/จังหวัดตามพิกัด (`admIndex`) ไม่งั้นตามที่พิมพ์ · พิกัดใช้ไม่ได้ = `xy:2` ar "ไม่ทราบ (พิกัดใช้ไม่ได้)"
- `rp` ตัวเลือกฟอร์ม → ชื่อชุด Excel (`rpOf`): ดาวเทียม/NOAA… → ดาวเทียม (Hotspot) · จุดตรวจ/จุดสกัด/จุดเฝ้าระวัง/หอดูไฟ → ชุดจุดตรวจ/… · ลาดตระเวน → **ชุดลาดตระเวนและเฝ้าระวังไฟป่า** (Excel 2569 ใส่ "เครือข่าย อส.อส" 24 แถว — เลือกตามความหมายจริง) · อส.อส. → เครือข่าย… · ประชาชน → ชาวบ้านในพื้นที่ · อากาศยาน (ช่องใหม่)
- `cs` (`csOf`) → [ชื่อ, รายละเอียด]: ไม่ทราบ/ไม่ → ไม่ทราบสาเหตุ · ข้อความฝึกยิงปืน → ฝึกซ้อมยิงปืนของทหาร · กัมพูชา/ไฟข้ามเขต → ไฟข้ามเขตจากประเทศเพื่อนบ้าน · ข้อความ >40 ตัว → สาเหตุอื่นๆ + รายละเอียด (`cd`) — ตรง Excel ทุกแถวยกเว้น 1
- `fr` พื้นที่ป่าตามรายงาน (`frOf`) ชื่อเดียวกับ import_fx forest() · `st` (`stOf`): สถานีฯ ในฟอร์ม (+`STRN` เปลี่ยนชื่อ) → "อื่นๆ" = สถานีฯ/อุทยานฯ ในช่องหน่วยงานที่ร่วมบูรณาการ → อุทยานฯ ตามพื้นที่ป่า → ดงใหญ่ → สถานีฯ ตามแนวเขต
- `du` = รับแจ้ง → ดำเนินการเสร็จ (นาที, ≤7 วัน; หน้าเว็บตัดเกิน 12 ชม. ตามกติกาเดิม) · ไม่มีเวลาเข้าดับ (`ra` null) · `hs` จากช่อง "จุดที่ตรวจพบไฟ" (0 ตรง / 1 ไม่ตรง / 2 ระบุภายหลัง) — ไม่ได้คำนวณจากจุดกรมอุทยานฯ แบบแถว Excel
- `op` = จำนวนคน · หน่วยงานที่ร่วมบูรณาการ · เก็บ `sev sts grp ft hid src` ไว้แสดงในป๊อปอัป

## สายงาน
- `build_site.js` `dnpform()`: ดึงไม่บ่อยกว่า `DF_MIN` 15 นาที (ผลรอบก่อนใน `STATE_DIR/dnpform.json` — site.yml load/save state) · `DF_FORCE=1` ดึงทันที · ดึงไม่ได้ = ใช้ผลรอบก่อน `src:'state'` + `err` · ไม่มีรอบก่อน = `src:'none'` → `_site/dnpform.json` `{generated, src, sheets:[{k,raw,tab,n,err}], rows}` (~90 KB ปีงบ 2569)
- health `dnp` (`chkDnp`): ไม่มีไฟล์ · `src none` · `state` เกิน 6 ชม. · แท็บอ่านไม่ได้ทั้งคู่ · 15 ม.ค.–30 เม.ย. ไม่มีรายการปีงบปัจจุบันเลย (ฟอร์มใหม่?) · ทวนทุก 24 ชม.

## หน้าเว็บ (`index.html` ต่อจาก vfSetup)
- `DNF` (`var` — ชื่อ `DF` เป็นตัวแปรภายในโมดูลพื้นที่เผาไหม้) · `dfLoad()` 1.5 วิหลังโหลด + ทุก 5 นาที: `dnpform.json` (http) → `EMB_SITE` (file:// / serve.js ที่ราก)
- `dfXT()`: ลบแถว vf/df ท้าย XT → เติมแถว df **เฉพาะปีงบที่ไม่มีใน Excel อส.** (`DNF.fys` = ปีงบของ XT ตอนเรียกครั้งแรก) → `vfXT()` เติมแถว VF ต่อท้าย (vfXT ลบเฉพาะ vf) → `fdRender` ถ้าการ์ดเปิด + `srcUpd`
- ป๊อปอัป `xtPopup`: แถว df มี "ที่มา" (`dfSrc`) + "จุดความร้อน (ตามแบบรับแจ้ง)" แทน Suomi NPP · ตารางรายละเอียดนับ "+ แบบรับแจ้งเหตุ กรมอุทยานฯ n ครั้ง" · `x-src` และ `fd-src` บอกแหล่ง/เวลาข้อมูล
- **ฟอร์ม FD ซ่อน**: ไม่มี `#fd-add`, `#vf-fd` · `?fd=new` = เปิดการ์ดอย่างเดียว · โค้ด `fdForm` คงไว้ (แก้ไข/ลบบันทึกเดิมจากรายการล่าสุด)
- ทดสอบ: `test/dnpform.test.js` (gviz จำลอง: ไม่ขอคอลัมน์ส่วนบุคคล, กรอง สบอ., รวมแท็บ, แท็บล้ม, dt, ชื่อ, STRN 3 ชุดตรงกัน, dfXT) · `test/health.test.js` "dnp" · check_site ขั้น `FDSRC` (ไม่มีปุ่มฟอร์ม + บรรทัดที่มาบอกแบบรับแจ้งเหตุ)
