# ส่งบันทึกการดับไฟป่าเข้าแบบรับแจ้งเหตุไฟป่า กรมอุทยานฯ (Google Forms) — prefix `DF`

สถานะ (19 พ.ย. 69): **ขั้นทดสอบ** มีแค่สคริปต์สร้างฟอร์มสำเนาสำหรับทดสอบ ยังไม่มีโค้ดส่งในเว็บหรือ Worker

## ที่มา
- ผู้ใช้ขอ 19 พ.ย. 69: บันทึกการดับไฟในเว็บ (FD, `kd:'fd'` → [ui-modules.md](ui-modules.md)) แล้วให้ไปลงแบบรับแจ้งเหตุของกรมอุทยานฯ อัตโนมัติ เจ้าหน้าที่จะได้ไม่ต้องกรอกซ้ำ (ปีงบ 2570)
- **ฟอร์มจริงเก็บอีเมลแบบยืนยันตัวตน** (`info[10][6]=2`, หน้าแสดงช่องติ๊ก "บันทึกอีเมลของฉันพร้อมกับคำตอบของฉัน" + `data-user-email-address`) ผู้ส่งต้องล็อกอิน Google ในเบราว์เซอร์ของตัวเอง → **Worker ส่งแทนไม่ได้** (ไม่มีคุกกี้ Google ของเจ้าหน้าที่) · การล็อกอินด้วย Google บนเว็บเราก็ไม่ช่วย (Forms API ส่งคำตอบไม่ได้)
- แนวทางที่ทำได้: **ลิงก์กรอกล่วงหน้า (pre-filled)** บันทึกในเว็บแล้วเปิดฟอร์มที่ถูกต้อง (สบอ.1/7) ที่เติมค่าครบ เจ้าหน้าที่ตรวจแล้วกดส่งเองจากบัญชี Google ของตัวเอง · ส่งเฉพาะครั้งแรก (แก้คำตอบภายหลังไม่ได้ ถ้าส่งซ้ำจะเกิดแถวซ้ำ)
- อัตโนมัติเต็มรูปแบบต้องได้ความร่วมมือจากผู้ดูแลฟอร์ม เช่น ให้บัญชีบริการของเว็บมีสิทธิ์แก้ตารางคำตอบ (เขียนแถวลงตารางตรงๆ ไม่ผ่านฟอร์ม) หรือเปลี่ยนการเก็บอีเมลเป็นแบบพิมพ์เอง (ลดการยืนยันตัวตน ไม่แนะนำ)
- ทดสอบกับสำเนา (19 พ.ย. 69, สำเนารุ่นแรกเก็บอีเมลแบบพิมพ์เอง): POST `formResponse` + `emailAddress` + `pageHistory=0,1,3,5` + `fbzx` → ได้หน้า "บันทึก…เรียบร้อยแล้ว" · ลิงก์ `viewform?usp=pp_url&entry.N=…` (~2,500 ตัวอักษร) เติมค่าครบ วันที่+เวลาใช้รูป `YYYY-MM-DD HH:MM`

- **เลือกฟอร์มจากพื้นที่ป่าที่เกิดไฟ** ไม่ใช่จากสถานี: สถานีควบคุมไฟป่าเขาใหญ่ ทับลาน วังน้ำเขียว และดงใหญ่ อยู่ในรายการของฟอร์ม สบอ.7 แต่ในตารางคำตอบ สบอ.1 มีไฟในพื้นที่เรา 131 ครั้ง (ม.ค.–เม.ย. 69) และ 96 ครั้งเลือกสถานี "อื่นๆ"
- ทั้งสองฟอร์มมี 33 ข้อ (รวมส่วน) **และรหัสช่อง `entry.N` เหมือนกัน** ต่างกันเฉพาะตัวเลือกในดรอปดาวน์ · หน้า viewform เปิดดูได้โดยไม่ต้องล็อกอิน แต่การส่งต้องล็อกอิน (อีเมลแบบยืนยันตัวตน) · ทุกข้อบังคับ
- ตัวตรวจ: X = `([0-9]{6})` · Y = `([0-9]{7})` · เบอร์ `(0)([6'8'9]{1})([0-9]{8})` · จำนวนจุด/หน่วย/คน = ตัวเลข · วันที่รับแจ้ง = วันที่+เวลา · กลุ่มไฟเดิม = วันที่
- **การข้ามส่วน**: พื้นที่เกิดไฟ ป่าอนุรักษ์/ราษฎรทำกิน → ส่วนป่าอนุรักษ์ แล้วข้ามส่วนป่าสงวน · ป่าสงวน → ส่วนป่าสงวน · นอกพื้นที่ป่าฯ → ส่วนตรวจพบไฟ · กลุ่มไฟเดิม → ส่วนวันที่กลุ่มไฟเดิม · ใน `FB_PUBLIC_LOAD_DATA_` ส่วน (ชนิด 8) ช่อง `[5]` คือ "หลังจบส่วนก่อนหน้าไปที่ใด" (ความหมายเดียวกับ `PageBreakItem.setGoToPage`) ตรวจจากตาราง: แถว "ป่าอนุรักษ์" ช่องป่าสงวนว่างทุกแถว · ตัวเลือก `[2]` = ไปส่วนที่ระบุ, `[4]=1` และค่าว่าง = ช่อง "อื่นๆ" พิมพ์เอง
- ตาราง สบอ.1 มีคอลัมน์ที่ไม่อยู่ในฟอร์ม (สถานะของไฟป่า, ประมาณพื้นที่ไฟไหม้ (ไร่), วันเวลาที่ดำเนินการเสร็จ, ระดับความรุนแรง, ระยะเวลา) ผู้ใช้ยังไม่ได้ตอบว่าใครเป็นคนเติม
- ค่าที่พบบ่อยในพื้นที่เรา: ID (Hotspot) = "ไม่มี" 77/131 · กลุ่มไฟใหม่ 125/131 · ราษฎรทำกิน 22/131 · มีคนพิมพ์ "ดาวเทียมNOAA20/21" ในช่องอื่นๆ ของตรวจพบไฟจาก
- **ห้ามส่งทดสอบเข้าฟอร์มจริง** (จะเกิดแถวปลอมในตารางราชการ) ให้ทดสอบกับฟอร์มสำเนา · ไม่ใส่ลิงก์ตารางคำตอบของกรมฯ ใน repo (เปิดอ่านได้โดยไม่ต้องล็อกอิน และมีอีเมล/เบอร์โทรของเจ้าหน้าที่)

## ฟอร์มสำเนาสำหรับทดสอบ — `scripts/gas/dnp_form_copy.gs`
- Apps Script ผู้ใช้รันเองที่ script.google.com: วางทั้งไฟล์ → เลือก `makeCopies` → เรียกใช้ → อนุญาต (Forms, Sheets, บริการภายนอก) → ลิงก์จะอยู่ในบันทึกการดำเนินการ
- `dnpCopyFromUrl` อ่านหน้า viewform สาธารณะ (GET อย่างเดียว) → `dnpLoad` (`FB_PUBLIC_LOAD_DATA_`) → `dnpBuild` สร้างฟอร์ม "[ทดสอบ] …" ที่มีคำถาม ตัวเลือก ช่องบังคับ ตัวตรวจ (`dnpValid`) และการข้ามส่วนเหมือนเดิม + เก็บอีเมลแบบพิมพ์เอง + ตารางคำตอบ
- **รหัส `entry.N` ของฟอร์มสำเนาไม่ตรงต้นฉบับ** → โค้ดส่งต้องจับคู่ช่องจากชื่อคำถาม (อ่าน `FB_PUBLIC_LOAD_DATA_` ของฟอร์มเป้าหมาย) ไม่ฝังรหัสไว้ตายตัว
- เทสต์ `test/dnp_copy.test.js` รันสคริปต์กับ FormApp จำลอง โดยใช้ fixture `test/fixtures/dnp_form_sbo1.json` / `dnp_form_sbo7.json` (โครงสร้างฟอร์มวันที่ 19 พ.ย. 69)
- ผู้ใช้รันจริงแล้ว 19 พ.ย. 69 (รุ่นแรก): ได้ 28 คำถาม ตัวเลือกและการข้ามส่วนตรงต้นฉบับ (เทียบ `FB_PUBLIC_LOAD_DATA_` ของสำเนากับต้นฉบับ) แต่**มีจุดต่าง 2 จุด** (1) อีเมลเป็นแบบพิมพ์เอง → แก้สคริปต์ให้ใช้แบบเดียวกับต้นฉบับ (`info[10][6]`: 2 = `VERIFIED`, 3 = `RESPONDER_INPUT`) (2) "วันที่และเวลารับแจ้งเหตุ" ไม่มีเวลา (`a[7]=[null,1]`) ทั้งที่เรียก `addDateTimeItem` → ตัดการเรียก `setIncludesYear` กับวันที่+เวลาออก (ยังไม่รู้สาเหตุแน่ชัด; ยังไม่ได้รันรุ่นแก้) · สำเนาที่สร้างไปแล้วแก้เองในหน้าแก้ไขฟอร์มได้

## งานถัดไป (รอผู้ใช้)
1. ผู้ใช้รัน `makeCopies` แล้วส่งลิงก์ฟอร์มสำเนา 2 ลิงก์มา
2. ตัดสินใจเรื่องช่องที่เพิ่มในฟอร์ม FD (พื้นที่เกิดไฟ ป่าอนุรักษ์/ราษฎรทำกิน, กลุ่มไฟใหม่/เดิม, ID Hotspot, ป่าสงวน) และอีเมลในบัญชีพร้อมช่องยินยอม
3. ก่อนเปิดใช้กับฟอร์มจริง ต้องแจ้งศูนย์สั่งการหรือผู้ดูแลฟอร์ม สบอ.1/สบอ.7
